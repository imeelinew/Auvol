Auvol · macOS 菜单栏 UI 精修方案

上一轮已经把两端的信息语义对齐了，这一轮只处理 macOS 的视觉表达： 控件选型、层级、间距、颜色和状态可视化。信息字段、交互流程、传输逻辑都不动， 所以改动全部收敛在 mac/Auvol/StatusView.swift 一个文件里。 Windows 只做三处小幅对齐，不动结构。

本页是可交互的高保真效果稿：方向切换、开关、滑杆都能点，电平条按真实动态刷新。 弹窗按 1 CSS px = 1 pt 绘制，在 Retina 屏上就是实际尺寸。

01 现状诊断

按对界面「精致度」的影响从大到小排。前四条基本决定了整体观感。

1 滑杆的刻度点

Slider(in: 8...80, step: 1) 让 AppKit 画出 72 个 tick dot。那条虚线点阵是目前最刺眼的元素，也是唯一一处「像调试面板」的地方。

改：去掉 step，在 setter 里取整。

2 复选框样式的开关

SwiftUI 的 Toggle 在 popover 里默认渲染成蓝色 checkbox，是「偏好设置对话框」的语汇，不是菜单栏语汇。

改：.toggleStyle(.switch)，并缩到 .controlSize(.small)。

3 满宽实心蓝分段控件

选中段整块填蓝，在 300pt 宽度里视觉重量过大，抢走了本该属于「当前状态」的注意力。

改：灰底轨道 + 白色浮起胶囊，蓝色只留给状态语义。

4 三条全宽 Divider

分组靠 Divider() 硬切，且切得不匀：自动跟随和连接之间没有分隔，缓冲前后各一条。看不出哪些字段属于同一组。

改：分组用圆角卡片，组内用缩进细线。

5 字号层级压得太扁

caption2 + .tertiary 用得过多：耳机名「WF-1000XM5」和状态「已连接 · 传入音频静音」都是最弱的灰色小字，而它们其实是主信息。

6 状态点没有说明

右上角 8pt 圆点是唯一的全局状态指示，没有文字，颜色含义要靠记。下方还另有一行「链路」，两处状态互不呼应。

7 音频 App 却没有电平表

信号只有一行「静音」或 -18.4 dBFS。一个 4pt 的电平条能在 0.2 秒内回答「到底通没通」，是性价比最高的一处增强。

8 底部两个同权重文字按钮

「暂停」和「退出」都是 borderless 文字、同色同号、并排贴右下角。主操作和破坏性操作没有区分，还容易误点。

9 完全没有图标

Windows 每行都有 FontIcon 做视觉锚点，macOS 一个 SF Symbol 都没有，扫读时只能逐行读字。

10 内容顶边

文字直接贴在 popover 的毛玻璃上，没有承载面。所有行等宽等重，缺少「块」的概念。

· 保持不变

字段集合、中文文案、方向语义、菜单栏 wave.3.forward 三态配色，全部沿用上一轮的结论。

✓ 已经对的地方

320pt 以内的窄弹窗定位、接收/发送两态复用同一布局、中文状态映射表，这些结构是对的，只换表现层。

02 设计原则

四条，用来在后续每个取舍上做判断。

① 一眼看状态

打开弹窗后第一屏必须回答三件事：通没通、往哪个方向、有没有声音。 这三件事全部集中在顶部的状态区，其余都是次要信息。

② 颜色只表达状态

蓝 / 橙 / 红只用于「传输中 / 已暂停 / 异常」，并且同时驱动菜单栏图标、状态胶囊、图标底色、电平条、滑杆和主按钮。 控件本身不主动用彩色。

③ 分组用面，不用线

相关字段收进圆角卡片，卡片内部用缩进 0.5pt 细线；卡片之间用 10pt 留白。全宽 Divider 一条不留。

④ 沿用系统语汇

参照「控制中心 / 系统设置」的行式布局：22pt 圆角图标块 + 标题/副标题 + 右侧控件。 不自造控件外形，只自造排布。

03 改版对照

同一场景：接收 Windows 音频、有线链路、自动跟随 WF-1000XM5、缓冲 12 ms。左边是现在，右边是方案。

1× 即 Retina 屏上的真实物理大小

04 状态矩阵

同一套布局在其余场景下的样子。所有差异都由一个 tone（蓝/橙/红）+ 文案驱动，没有额外分支布局。

电平条的映射

-60 dBFS → 0%，0 dBFS → 100%，线性夹取。 hasSignal == false 时填充置灰、宽度归零，数值位显示「静音」。

峰值线保持 1.2 秒后以 24 dB/s 回落，这是它比裸数字更好读的原因。

状态胶囊的取值

只有三种：传输中（isPlaying || isSending）、已暂停（isPaused）、异常（其余）。 它和菜单栏图标颜色永远同源，读同一个计算属性。

圆点在「传输中」时做 2.1 秒一次的呼吸扩散，其余状态静止。

分段控件不放箭头图标

Windows 的方向按钮带 ↑ / ↓ 图标，含义是「相对本机的流入流出」。 同一个标签在两台机器上箭头方向必然相反，而你是两台一起看的。

macOS 这侧的标签本身已经写了 →，再加图标是冗余且会自相矛盾，所以只留文字。

Liquid Glass 可选增强

当前部署目标是 macOS 14.2，上面的效果全部用材质 + 不透明度实现，14 起就能跑。

若愿意抬到 macOS 26，可在 #available 分支里给状态区和主按钮加 .glassEffect(.regular.tint(tone))，其余不变。

06 Windows 端微调

结构、卡片、Mica、文案全部保留。只有三处，目的是让两端在「状态」和「方向」这两个共享概念上长得一致。

1 状态点 → 状态胶囊

现在是 Ellipse + 独立 TextBlock，两个元素靠 8pt 间距拼在一起。 换成一个带 11% 主题色底的 Border，内部圆点 + 文字，和 macOS 的胶囊一一对应。

文件：MainWindow.xaml 的 StateDot / ConnectionStateText。

2 信号行加电平条

目前只有一个 SignalValue 文本。在它左边插一个 150px 宽、4px 高的 ProgressBar（或 Rectangle + 宽度绑定）， 映射规则和 macOS 完全相同（−60…0 dBFS）。这是两端观感差距最大的一处。

3 两个 ToggleButton → SelectorBar

现在的 SendModeButton / ReceiveModeButton 是一对手动互斥的 ToggleButton， 选中态是完整按钮填充，比 macOS 那侧重。换成 WinUI 3 的 SelectorBar， 选中态是下划线，视觉重量和「灰底白胶囊」接近，互斥逻辑也由控件自己管。

如果不想动代码逻辑，退而求其次：保留 ToggleButton，仅把选中样式换成 AccentButtonStyle 之外的次级样式。

不改的部分

Mica 背景、TitleBar、三段式分节标题、InfoBar、卡片圆角 8、960px 最大宽度、所有文案， 全部维持现状。Windows 的信息密度和留白已经是对的。
